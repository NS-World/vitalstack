# VitalStack 4.20.2: sign out really signs out

## Problem
After signing out, the next sign-in skipped the emailed code and signed the reader straight in.
Cause: the browser was marked "trusted" (automatically after sign-up, and by the pre-ticked
"Trust this device for 30 days" box on the code screen), and signing out did not clear it.
With one device at a time, a device that another sign-in had pushed out could also come back without a code.

## Fix (additive: new `inc/auth-flow.php`, nothing else changed)
- **Sign out** forgets this browser's trust and drops any half-done code attempt.
  The next sign-in is always password + email code (or authenticator app code).
- **New sign-in** keeps the trust of the current browser only. Every other browser was just signed
  out (one device at a time), so it must use the full flow again.
- "Trust this device" now means only: if the session simply runs out on this browser without a
  sign-out, the reader is not asked for a code again for 30 days.

## Flows (all tested, 40/40, `t4202.js`)
**Sign-up:** details → "Confirm your email" screen (masked address) → wrong code shows an error →
right code creates the account, signs in, shows the welcome message, and sets subscribed + verified.
The email box is pre-ticked (unticked for EU/UK).

**Sign-in:** email + password → "Two-step sign-in" code screen → right code signs in
("You are signed in."). Readers with an authenticator app get the app screen instead, with no email sent.

**Errors:**
- wrong password: "don't match" message;
- wrong code: "isn't right";
- 5 wrong codes: "expired / tried too many times";
- Resend: "New code sent", and the old code stops working;
- Cancel: back to the form;
- wp-login.php: refuses a reader's password on its own.

**One device:** a sign-in on the phone signs out the laptop, with popups on both. The laptop then needs password + code.

Tested on a phone: the code screen fits the width, and there are no JS errors.
