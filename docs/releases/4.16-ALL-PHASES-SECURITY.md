A free, day-by-day plan for learners without a mentor:

How it works:

  to premium readers).

  - the module guides;
  - the assistant's beginner answer.
- **SEO:** its own title, description and canonical.

## 4. Phase 3: Website Playground (`/playground/`)

Build a real multi-page website in the browser:

- **Files:** `index.html`, `style.css`, `script.js`, plus your own pages ("+ Page"). Links between
  pages work in the preview.
- **Preview:** it updates live, with **phone (375 px), tablet (768 px) and full width** buttons,
  and a console that shows `console.log` output and errors.
- **Templates (original):**
  - 2-page portfolio (with dark mode);
  - café landing page with a menu filter;
  - tech event with a countdown;
  - blank page.

  A template opens as a new project, so other projects are kept.
- **Saving:** projects are saved on the learner's device. The project menu switches between them.
- **Free:** "Download HTML" gives one file with the CSS and JavaScript inside.
- **Premium:** "Export ZIP" gives the whole project with every file, ready for GitHub Pages or
  Netlify. Visitors see a link to the plans instead.
- **Phones:** Code / Preview tabs.
- **Where it is linked:** the 🎮 Break zone's Tools tab and the assistant's tools answer.

**Why it is safe:**

- **Sandbox:** the preview runs in a sandboxed frame without "same origin". The learner's code
  can't read the site's cookies, storage or pages, or act as the signed-in user.
  - Tested: cookie, storage and parent page access all end in `SecurityError`.
- **No network:** a Content-Security-Policy inside the preview blocks network requests
  (`connect-src 'none'`) and form posts, so code there can't send data anywhere.
  - Tested: `fetch` is blocked.
- **Messages:** the site only accepts messages from that preview frame (tested: forged messages
  are ignored).
- **Console:** console output is shown as text only (tested with an `<img onerror>` attempt).
- **No uploads:** nothing is uploaded, and there is no new server endpoint.

The ZIP button is a convenience feature for Premium. It runs in the browser, so a technical user
could unlock it from the developer tools. It protects no data or money, which is why it is fine
for it to be client-side.

## 6. Security review of everything added since 4.13.3

No developer can honestly promise "zero vulnerabilities" forever. New attacks appear, and
plugins, WordPress and hosting matter as much as the theme. Here is exactly what was checked,
what was fixed, and what to keep doing.

**Automated scan:**

- **Setup:** Semgrep with WordPress security rules written for this review. They look for:
  - request data printed without escaping;
  - SQL without `prepare`;
  - `eval`/`exec`/`unserialize` of input;
  - REST routes without a permission check;
  - open redirects;
  - `innerHTML`/`eval`/`document.write` in JavaScript.
- **Scope:** the whole theme and both plugins (the online rule library is blocked in this
  environment).
- **Result:** 47 matches, all reviewed by hand:
  - **4 PHP:** false positives. Two SQL queries contain only table names (no user input). Two REST
    routes do have `permission_callback` (in a nested array the rule didn't read).
  - **43 JavaScript `innerHTML`:** each traced to its source:
    - static SVG characters;
    - text passed through `esc()`;
    - or lesson content written by the site admin.

    None takes another visitor's data unescaped.
  - **One hardening fix:** the confidence level in the sample-size tool is now escaped too. It
    could only ever be the reader's own input.

**Secrets:** the repository has no keys or passwords. The only match is the placeholder
`rzp_live_xxxxxxxx` in the payments guide.

**Third-party scripts:** only two, both pinned to exact versions and only on the tool pages:

- sql.js 1.10.3 (SQL playground);
- Pyodide 0.26.4 (Python compiler).

**Security headers** on the new pages: `X-Content-Type-Options`, `X-Frame-Options`,
`Referrer-Policy` and `Permissions-Policy`.

**Manual review of new code (4.13.4 – 4.16.0):**

| Area | Finding |
|---|---|
| Offer strip, module guides, study plan | All output escaped; no input taken |
| Assistant | Runs in the browser from public facts; replies built as text; data JSON-escaped in the page |
| Break zone | No input sent anywhere; text only |
| Marketing plugin | Admin-only (`manage_options`) with nonces; campaign HTML filtered with `wp_kses_post`; subject and sender name sanitised (no header injection); SQL through `WP_User_Query` and `$wpdb->prepare`; only consented, confirmed subscribers; one-click unsubscribe |
| Festive plugin | Admin-only with nonces; colours through `sanitize_hex_color`; the preview parameter works only for admins |
| Email check | Admin-only; the test email needs a nonce |
| Playground | Sandboxed frame, CSP, message checks, file names sanitised, text-only console |

**What keeps the site safe in practice (please do these):**

1. **Cloudflare (free)** in front of the site, with Bot Fight Mode and the managed WAF rules.
2. **Two-factor login** for every admin account, and unique strong passwords.
3. **Updates:** keep WordPress, PHP (8.1+), plugins and the theme up to date. Delete plugins you
   don't use.
4. **Backups:** daily backups in hPanel, with one copy off the server.
5. **Malware scanner:** hPanel → Security → Malware scanner on.
6. **SMTP:** set it up, and keep **Tools → Email check** green.
