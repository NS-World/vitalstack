# VitalStack 4.20.1: sign-in codes keep arriving

## Problem
After an SMTP plugin (WP Mail SMTP) was installed, sign-in / sign-up codes stopped arriving
(neither inbox nor spam). When the SMTP setting is wrong (password, port, From address the
mailbox does not own) every email fails, so readers cannot sign in.

## Fix (additive, no existing behaviour changed)
- New `inc/mail-fallback.php`.
- When a theme email fails through an SMTP plugin, it is sent once more with the server's
  built-in mail (how it went before the SMTP plugin, and how codes reached the inbox earlier).
- The SMTP error is saved (emails and passwords masked) and shown to admins as a red notice in
  wp-admin with the exact fix steps. It disappears by itself once an email goes through SMTP again.
- `vitalstack_mail()` in `inc/notifications.php` calls the retry only when `wp_mail()` returned false.
- Filter `vitalstack_mail_fallback` (return false to turn the backup off).

## Tests
- Fake failing SMTP: code delivered via built-in mail, error recorded, notice admin-only,
  no secrets stored, cleared after a normal send, false when backup is off.
- Regression: one-device 19/19, local sign-up + sign-in end-to-end 25/25, charts 19/19,
  full-site 1068 checks, tools 356, pages 189, runner 141: all pass. Semgrep: no new findings.

## What the admin should still do
WP Mail SMTP → Tools → Email Test. If it fails, fix: host `smtp.hostinger.com`, port `465`, SSL,
username = full mailbox (`contact@vitalstack.co.in`), that mailbox's password, From Email = same
mailbox, "Force From Email" on. Until fixed, codes still go out (backup), but may reach spam more.
