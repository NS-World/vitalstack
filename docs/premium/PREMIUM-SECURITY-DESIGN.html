5. Premium lesson standard

Every premium lesson follows one template so it works for a struggling student and a topper alike:

  1. Goal and time: what you will be able to do, in how many minutes.
  2. Animated visual (viz.js) of the idea before any code.
  3. Two depths: a Simple explanation and a Deep dive switch for toppers.
  4. Line-by-line code: every line has its own explanation; tapping a line highlights it in the animation.
  5. Try it: editor with automatic checks.
  6. 3-question quiz, then a mini task.
  7. Interview questions and a recap card. Study buddy question halfway; XP on finish.

Quality gate: every code sample is run by an automated test before publishing, with library versions pinned.

8. Payment flow

Figure 3. Steps 1–10 already exist; this design adds the step-up checks in step 2, invoice numbers, and the later webhooks.

Payment additions

  • Monthly via Razorpay Subscriptions (UPI AutoPay / card mandate), with a reminder email 3 days before each charge.
  • Sequential invoice numbers (VS/2026-27/0001), buyer name and optional GSTIN, sent as a PDF. Tax rules: confirm with a CA (GST registration, rates for online education).
  • Refund or dispute webhook removes access at once and logs it.
  • Daily reconciliation: compare Razorpay captured payments with orders; email the admin about any mismatch.
  • Alert if a payment is captured but access is not granted within 10 minutes.

9. Sign-in, 2FA and the device limit

Figure 4. Sign-in for premium readers. Free readers can keep password-only sign-in until they buy.

  • 2FA choices: authenticator app (Google Authenticator, Microsoft Authenticator; recommended) or a 6-digit email code. Ten one-time backup codes at setup.
  • Device rule: one phone or tablet, and one laptop or desktop, signed in at the same time. Signing in on a third device asks to sign out the old one of the same type, with an email code. At most 3 switches in 30 days; after that, support checks the account.
  • How a device is recognised: a random device token in a secure, HttpOnly cookie, linked to the session on the server. The device type comes from the browser and can be faked, so the rule is backed by watermarks and alerts.
  • Sessions: 30 days, renewed on use, revocable from “My devices” in the account page. Password change signs out every device.
  • Lost phone: use a backup code, or support verifies the order ID and email.
  • Admins: authenticator app required (no email codes), 12-hour sessions, email alert on every admin sign-in from a new device.

  • Workspace rule: every saved item stores its owner. Each API call checks owner = signed-in reader, a fresh nonce, input size and type, and a rate limit. Readers can never change lesson content, only their own workspace.
  • Content cannot be edited by outsiders: readers have no editing rights; the wp-admin file editor is off (already live); editors and admins need 2FA; every content change is kept as a revision and written to the audit log; theme files are deployed only from Git, and a file-integrity check emails the admin about any unexpected change.

13. If content leaks

  1. Read the watermark in the leaked image or text (visible ID, or the invisible pattern via an admin tool).
  2. Check that reader's access log to confirm.
  3. Suspend the account at once (one click), and sign out every device.
  4. Send takedown notices to the platform (Telegram, YouTube, Google, file sites).
  5. Close the account under the Terms (no refund for sharing), and keep a record.
  6. If the same lesson leaks again, change its invisible watermark pattern.
